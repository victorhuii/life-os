# V.E.C.T.O.R. Mail Lab

Groups uses separate topics per inbox: Main has Promotion / shopping, Jobs, School, and Other / random; Berk has School, Job, Work, and Random; Cal Hacks has General, Spons, and Me. Spons means sponsorship and company-partner conversations. Me means personal messages or requests specifically for Victor; sponsorship-related requests remain in Spons. Needs attention remains the default inbox view. Read and hidden states remain separate from topic classification. No Google labels or email state are changed by classification.

## Models

- **Starter:** a small TF-IDF logistic-regression model trained from hand-authored synthetic examples appropriate to each inbox. It provides immediate suggestions; it is not a validated email classifier.
- **Pretrained voting ensemble:** pinned int8 ONNX versions of [DeBERTa xsmall](https://huggingface.co/Xenova/nli-deberta-v3-xsmall), [DistilBERT MNLI](https://huggingface.co/Xenova/distilbert-base-uncased-mnli), and [MobileBERT MNLI](https://huggingface.co/Xenova/mobilebert-uncased-mnli). Three distinct pretrained NLI models perform zero-shot topic classification with inbox-specific descriptions. This is a voting ensemble, not a random forest or a new trained model. Two matching votes choose the category. A three-way split gets a deterministic provisional suggestion (mean score breaks the tie) and a review flag. Vote agreement is not calibrated confidence or accuracy. Each vote is saved immediately, and an interrupted batch resumes only missing votes. Models run sequentially in workers to bound memory; automatic batches rotate across the three inboxes, eight messages per batch, while the app is visible. Pause/Resume automatic is available in Mail Lab. First use downloads each model; subsequent workers reuse cached assets where storage permits.
- **Personal:** a fresh TF-IDF / regularized multiclass logistic-regression model trained in a browser worker using reviewed labels and synthetic starter examples. This does not fine-tune DeBERTa. At least 8 reviewed messages in the selected inbox across 2 classes unlock training. Datasets, active models, history, inference candidates, and metrics are isolated by mailbox; a model from another inbox cannot be activated or used. Reviewed examples receive higher sample weight; class balancing and L2 shrinkage reduce majority-class dominance. Feature vocabulary is bounded at 1,600 unigrams, bigrams and sender domains.

A reviewed label always wins. Otherwise, a completed three-model vote supplies the automatic group; until it finishes, the active personal model, a compatible legacy DeBERTa suggestion, or the starter supplies a fallback. Automatic predictions never become reviewed training labels. Model scores are not calibrated probabilities or measured accuracy. Messages are classified from sender, subject and saved preview; the full email body is not used. Review and semantic classification use the selected Past week or Archive range. Weekly imports follow every Gmail page; older received mail loads on demand in Inbox → Archive. Reviewed examples remain available for training across both ranges, regardless of which rows are displayed.

## Review and evaluation

Confirm a suggestion or choose another category in Groups / Mail Lab. Up to 1,000 reviewed examples and 1,000 cached semantic predictions persist independently of inbox refresh. Review only genuinely checked labels; suggestions never silently become ground truth. Reviewed examples can be removed and exported as JSONL. The active personal model can be exported as JSON.

Training is deterministic for a fixed reviewed dataset. Evaluation unions messages sharing a sender or repeated normalized subject and holds out whole groups. Classes need at least three distinct groups to supply a test group without exhausting training examples. Exact starter subject duplicates of held-out examples are removed from evaluation training. Vocabulary and weights are fitted only to evaluation-training data. Accuracy, macro F1 over supported classes, per-class support, and the confusion matrix are reported on held-out reviewed messages. If no eligible split exists, metrics remain absent. The final deployed personal classifier is then refit on all reviewed examples. This is a small personal validation split, not proof of general or enterprise-grade accuracy. Repeated evaluation on one dataset can overfit; independent and multilingual datasets, drift monitoring, calibration, bias analysis and larger benchmarks are future work.

Up to five personal versions per inbox are retained, with rollback or a switch back to Starter / DeBERTa. The dataset fingerprint prevents a model trained on stale labels from replacing the current model. New labels visibly flag the active model for retraining.

## Data and runtime

`/api/mail-classifier` requires authenticated same-origin mutations and reads only verified mailbox/message identities. Dataset, models and predictions use separate D1 record kinds and are excluded from dashboard state and ordinary workspace exports. They are shared only within this existing owner-private site.

`public/mail-semantic-worker.js` loads a pinned public Transformers.js module, WASM and model assets. `/api/mail-model/[...file]` streams an allowlist of files from three allowlisted, pinned Hugging Face repositories/revisions after authentication, avoiding browser cross-origin download failures. It never accepts an arbitrary upstream URL and never forwards Gmail credentials. Downloaded weights are cached by the model runtime where browser storage permits. Inference and personal training run on the user's device; email text is not sent to Hugging Face. Model acquisition still needs a network connection. Slow devices, download failures and memory constraints surface actionable errors while starter grouping remains available.

No claim of perfect accuracy is made. Other is a real class; low confidence is surfaced for review rather than relabeled as Other.

## Validation

- `node scripts/test-mail-classifier.mjs`: learned starter and personal inference, grouped holdout, missing-metric behavior, account isolation, label/model persistence, rollback, fingerprint checks, authentication, CSRF and narrow model-asset proxy.
- `npm run typecheck` and the production Sites build.
- Browser QA with fixture emails: Groups, review, actual training worker, holdout display, rollback, mobile layout, and actual pinned DeBERTa download/inference. No personal messages are used for QA.

Primary references: [Transformers.js](https://huggingface.co/docs/transformers.js/en/index), [NLI model card](https://huggingface.co/cross-encoder/nli-deberta-v3-xsmall), [ONNX conversion](https://huggingface.co/Xenova/nli-deberta-v3-xsmall).

## Existing-data compatibility

Main keeps compatible reviewed labels and semantic predictions. Earlier global models are used for Main only when their stored dataset fingerprint and example count prove they were trained solely on Main’s currently reviewed data. Models mixing inboxes and old Cal Hacks topic labels remain in storage but are excluded from current grouping/training; messages can be reviewed under the new categories. Berk retains compatible School/Job/Random labels. Obsolete four-class semantic predictions for Berk or Cal Hacks are ignored, and new predictions carry an inbox-specific taxonomy tag.

## Inbox state

The header counts reviewed emails in the selected current, non-hidden inbox and separately names its category count. Training counts include saved reviewed examples that are hidden or have left the latest inbox snapshot; the review queue explains that difference. Classification coverage is recomputed from that same current inbox using reviewed labels and matching saved semantic predictions, so it survives reloads and changes when messages change. Download, stop, error and training status belong to the account that started them. A single browser inference worker runs at a time; another inbox shows its own coverage and identifies which inbox is busy.

## Ensemble cache and status

The panel shows **Model voting**, model names, automatic status, per-inbox completed coverage, and Pause/Resume. A completed email has three votes or a reviewed label. Partial votes do not count as complete. The existing `transformers-cache` Cache Storage bucket retains earlier DeBERTa downloads. DistilBERT and MobileBERT have separate versioned asset paths. The saved-device indicator probes all three weight files. Only actual cache misses show downloading progress. Cache access/write failures remain nonfatal and never claim files were saved. Browser eviction or clearing storage may require another download.

`/api/mail-classifier` validates the model allowlist, category dimensions, finite normalized scores, account/message identity, and current text fingerprint before deriving each model's vote itself. Compare-and-swap merges concurrent tabs without losing votes. It computes the final majority itself; the client cannot submit an arbitrary winning label. Manual labels use separate records and always take precedence. Topic voting and the independent attention task share a device inference lock. Closing/hiding the app stops topic inference; this is not unattended server inference.

Training validation also covers 64 confirmed emails after all 64 leave the weekly view: all examples remain in the saved dataset and the personal model trains with 64 examples.

Main's **Needs attention** view includes only unread, non-hidden emails whose current classification is **School** or **Jobs**. It uses the same reviewed-label / completed ensemble / personal fallback / legacy DeBERTa / starter precedence as Groups and reacts to label/model changes. Promotion / shopping and Other / random remain available in Groups and All saved; no Gmail labels, read states or messages are changed by this view filter. Main waits for classifier state before displaying this view, with a retry option if loading fails. Berkeley and Cal Hacks retain their existing attention rules.

Berkeley (`huiv@berkeley.edu`) now has **School, Job, Work, Random**. Work covers current employment/internship duties, colleagues, workplace projects, meetings, payroll and employee surveys; Job covers recruiting and applications. Berkeley's DeBERTa taxonomy cache tag is versioned independently, and older three-category personal models are retained in storage but cannot be activated against the new four-category taxonomy. Reviewed labels are preserved; retrain Berkeley's personal model to use Work. Main and Cal Hacks category sets are unchanged.

## Pretrained attention checks

All three inboxes' Needs attention views now run an independent **pretrained DeBERTa zero-shot action-detection pass**, using the existing pinned `Xenova/nli-deberta-v3-xsmall` ONNX weights. This is a separate inference task, not a newly trained model or an ensemble, and it does not use the personal topic model for its attention scores. It requests no reviewed attention labels and needs no training. Main still first restricts candidates to School/Jobs; Berkeley keeps all its categories eligible. Both retain unread/local-hide rules. Cal Hacks first keeps its verified conversation participation filter, then applies the attention pass.

The pass uses sender, subject and the saved message preview (up to the existing 2,000-character input limit), not the complete Gmail body or thread. It distinguishes requested replies/tasks/decisions/deadlines, informational mail, and unclear context. Independent entailment scores are used so the model need not force a category. A top score below 0.65, a margin below 0.15, or fewer than eight words of subject/preview context is uncertain; uncertain and unchecked messages remain visible. Only confidently informational results are filtered out. Results are suggestions, not calibrated probabilities or a guarantee that no important mail is missed. Groups and All saved retain informational messages.

Checks start automatically while a supported inbox's attention view is visible, process sequential batches of eight, pause when the browser tab/view closes, and offer Pause/Continue controls. Topic-model inference takes precedence to avoid running two transformer workers simultaneously. Model assets reuse the existing browser cache; cold use may download approximately 100 MB. Email text is passed to a browser worker and is never sent to Hugging Face. Authentication-protected `/api/mail-attention` saves only account-bound decisions, score vectors, text fingerprints and model-task version under `mail_attention`, with 2,000 retained checks per inbox. These records are excluded from dashboard exports and assistant context. Changed text or task versions invalidate previous checks. Auth, same-origin validation and mailbox identity checks apply before writes.

The specialized priority DistilBERT repository lacks the browser ONNX export needed here; the mmBERT repository returned an access error during evaluation. DeBERTa was selected for its already-verified runtime/cache compatibility, not a claimed head-to-head accuracy win. The attention pass itself uses one model; the separate topic grouping ensemble uses the three-model majority described above. No private-email fine-tuning of pretrained weights is performed. Real-browser smoke tests used fixture messages, including an interview reply and a lecture update explicitly requiring no response; separate API tests cover uncertainty, account isolation, stale inputs and persistence.
